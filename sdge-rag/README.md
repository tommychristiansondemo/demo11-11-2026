# SDGE Gas Ops Knowledge Assistant (RAG on AWS)

Internal Q&A assistant for gas utility employees. Employees ask natural-language questions about gas
operations, safety, maintenance, compliance and policy; answers are generated by Claude on Amazon Bedrock and
grounded in documents that administrators upload, with numbered citations back to the source passages.

**Live demo:** https://demo.awsteach.com (classroom demo; sample documents are fictional).
**Class Insights companion:** https://demo-insights.awsteach.com, which explains this deployment to students. It has a
chatbot over `projectknowledge.md`, live logs, LLM prompt and reasoning traces, and the resource inventory.
Students sign in with their Gas Ops account. See [insights/](#class-insights-companion-app).

## Architecture

```
                         us-east-1 (CloudFront requirements only)
                         ┌────────────────────────────────────────────┐
                         │ edge stack: ACM cert · WAF web ACL          │
                         │  (rate limit/IP · IP allow/block · AWS mgd) │
                         └────────────────────────────────────────────┘
 Browser ── demo.awsteach.com ──► CloudFront ──(/*)──► S3 SPA bucket (OAC)
                                     │
                                     └─(/api/*)──► API Gateway REST (us-east-2)
                                                   Cognito authorizer · API key · usage plan · throttling
                                                          │
 us-east-2 ───────────────────────────────────────────────┼──────────────────────────────────────
   Cognito user pool (self sign-up, roles → groups,       ▼
   optional SAML SSO)                              Lambda "api"  ──► Bedrock Claude Haiku 4.5 (Converse)
                                                          │      ──► Bedrock Titan Embeddings v2
   S3 docs bucket ◄── presigned PUT (admins)              ▼
        │ ObjectCreated                         Aurora PostgreSQL Serverless v2 + pgvector
        ▼                                       (RDS Data API, creds in Secrets Manager)
   Lambda "ingest": extract (PDF/DOCX/TXT/MD) → chunk → embed → upsert vectors
                    DLQ (SQS) on failure

   Parameter Store: model ids, top-k, max tokens · CloudWatch: JSON logs, EMF metrics, alarms → SNS,
   dashboard · X-Ray tracing · CodePipeline: S3 source → Validate → [Approval] → Deploy
```

**Design notes**

- **Vector store**: Aurora Serverless v2 + pgvector, queried with the **RDS Data API**, so Lambdas run without a VPC
  or NAT gateway. The DB sits in isolated subnets with no inbound rules. HNSW index, cosine distance, 1024-dim Titan v2 vectors.
- **Model**: Claude 3.5 Haiku and Sonnet have been retired from Bedrock, so the default is their successor
  `us.anthropic.claude-haiku-4-5-20251001-v1:0`. You can change the model with no redeploy by editing
  `/sdge-rag/<env>/chat-model-id` in Parameter Store (picked up within 5 minutes). Sonnet 4.6
  (`us.anthropic.claude-sonnet-4-6`) also works on this account.
- **Same-origin API**: CloudFront routes `/api/*` to API Gateway, so there is no CORS and everything sits behind WAF.
- **Roles**: users choose *Employee* or *Administrator* when they register (`custom:role`, immutable). A
  PostConfirmation trigger puts them in the `employees` or `admins` Cognito group, and the API enforces admin-only routes
  from the `cognito:groups` claim.
- **Demo auth settings**: password minimum is 6 characters with no complexity rules, and a PreSignUp trigger
  auto-confirms users, so there is no email verification. Any username works, and students can register as many
  accounts of each role as they want.
- **SSO**: set `SAML_METADATA_URL` in `infra/env/<env>.env` (Entra ID, Okta, ADFS or IAM Identity Center metadata) and redeploy.
  This creates a Cognito SAML IdP and the "Sign in with corporate SSO" button appears (hosted UI with code + PKCE).
  Federated users default to the `employees` group.

## Environments

Every resource name and stack name includes the environment (`sdge-rag-<env>-*`), so `dev`, `staging` and `prod` can
run side by side in one account. Defaults: `dev` → demo-dev.awsteach.com (DB scales to zero),
`staging` → demo-staging.awsteach.com, `prod` → demo.awsteach.com (DB minimum 0.5 ACU).

```bash
./scripts/deploy.sh prod                         # direct deploy (~20 min first time)
python3 scripts/e2e.py seed  https://demo.awsteach.com
python3 scripts/e2e.py smoke https://demo.awsteach.com

./scripts/deploy-pipeline.sh prod                # CI/CD; pass "true" to add a manual approval stage
./scripts/push-source.sh prod                    # triggers Source → Validate → Deploy
```

## Operations

- **Dashboard**: CloudWatch → Dashboards → `sdge-rag-<env>`. Shows API traffic and latency, chat volume and
  tokens, retrieval scores, ingestion results, Aurora ACUs and recent errors.
- **Alarms** (SNS `sdge-rag-<env>-alerts`): API Lambda errors, ingestion errors, ingestion DLQ, API 5XX, p90
  latency, Lambda throttles. Set `ALERT_EMAIL` in the env file to get email alerts.
- **Logs**: Lambda native JSON logs (`/aws/lambda/sdge-rag-<env>-*`), API Gateway access logs
  (`/aws/apigateway/sdge-rag-<env>-access`) and X-Ray traces.
- **Throttling**: the stage and usage plan limit requests per second and burst, and the usage plan also sets a daily
  quota. WAF blocks any IP that exceeds `WAF_RATE_LIMIT` requests in 5 minutes. Set `ALLOWED_CIDRS` to allow only
  corporate egress ranges.
- **Secrets**: the Aurora master password is managed by RDS in Secrets Manager. Runtime config lives in Parameter Store.
  The API key in `config.js` identifies the web client for usage-plan metering. It is not a secret; authorization comes from Cognito.

## Class Insights companion app

A separate application (`insights/`) with its own stacks: `sdge-insights-<env>-edge` in us-east-1 and
`sdge-insights-<env>-app` in us-east-2.

- **Static**: React SPA in its own S3 bucket behind its own CloudFront distribution, certificate and WAF.
- **Dynamic**: three Lambdas behind an HTTP API, all read-only.
  - `data`: UI panels (knowledge file, inventory, LLM traces, logs, metrics, alarms, pipeline).
  - `chat`: Claude Haiku 4.5 with extended thinking and 7 read-only tools.
  - `knowledge`: regenerates `projectknowledge.md`.
- **Auth**: the HTTP API's JWT authorizer trusts the Gas Ops Cognito user pool and app client. Students sign in
  with the same username and password; every role gets full access.
- **Knowledge file**: `s3://sdge-insights-<env>-knowledge-<acct>-<region>/projectknowledge.md`. This is the
  hand-maintained `insights/knowledge/narrative.md` (with verbatim system prompts filled in from source) plus a live
  inventory appendix. The appendix is regenerated on any `sdge-*` stack change (EventBridge), every 6 hours, and
  after each `deploy.sh`.
- **Reasoning logs**: both apps write `llm_trace` JSON log records with the prompt, retrieval evidence or tool
  calls, the model's extended-thinking text, the response, usage and latency.
- **No secrets**: the Lambda role has an explicit Deny on Secrets Manager, API Gateway (API key values), the RDS
  Data API and KMS decrypt. All output is passed through a redactor.

```bash
./insights/deploy.sh prod         # after scripts/deploy.sh prod
```


## Model Lab (switch the live LLM)

The **Model Lab** tab (any signed-in user) holds three linked sliders for quality, cost and latency. They always sum
to 100 and start at 50/25/25. **Evaluate & apply** benchmarks 8 Bedrock models from 6 vendors live: Claude Sonnet 4.6,
Claude Haiku 4.5, DeepSeek-R1, gpt-oss-120b, Mistral Large 3, Llama 4 Maverick, Nova Pro and Nova Micro. It ranks them,
and switches the live chat model when the best eligible model beats the current one by at least 2 points.

State lives in **AWS AppConfig** (`sdge-rag-<env>` / `<env>` / `model-selection`, JSON-Schema validated, instant
deployment strategy). `infra/model-catalog.json` seeds it on the first deploy only. The chat Lambda polls the AppConfig
data plane every 15 s. Code is in `backend/src/model_lab.py`. Test with `python3 scripts/e2e.py lab https://demo.awsteach.com`.


## Amazon Bedrock Knowledge Bases

Two managed KBs, both on **Amazon S3 Vectors** with Titan Text Embeddings v2:

- `sdge-rag-<env>-gasops-docs` indexes the same `uploads/` objects as the custom pipeline. It syncs after every
  upload, re-index and delete (`backend/src/kb.py`) and on deploy. Pick **Retrieval engine → Bedrock Knowledge Base**
  in the Ask tab to answer from it. Test with `python3 scripts/e2e.py kb https://demo.awsteach.com`.
- `sdge-insights-<env>-project-corpus` holds the design doc, the live inventory and a snapshot of the source code
  and IaC (`insights/kb_corpus.py`, which refuses to publish anything that looks like a credential). The Class
  Insights chatbot's `search_project_kb` tool uses it.


## Containers on AWS Fargate

Three workloads run as arm64 (Graviton) containers on ECS Fargate, in cluster `sdge-rag-<env>`:
- **Gas Ops API service.** API Gateway REST → VPC Link → internal NLB → tasks. Auto-scales from 1 to 4 tasks.
- **Ingest.** S3 → EventBridge → `ecs:RunTask`, one task per uploaded document.
- **Class Insights chat service.** HTTP API → VPC Link → Cloud Map. It has no load balancer.

The same handler code runs on both platforms. `backend/src/runtime.py` supplies the HTTP→event adapter,
Lambda-shaped JSON logs, metrics and Cognito JWT verification. Images are built by `scripts/build-images.sh` on a
Graviton CodeBuild project (stack `sdge-rag-<env>-containers`), so no local Docker is needed. Tags are content
hashes, and ECR tags are immutable. The Cognito triggers, the DB-schema custom resource and the Insights
data/knowledge functions stay on Lambda.
